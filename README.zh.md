# @ai-zen/cli

AI-Zen 宿主（host）的终端客户端。一条 WebSocket 上走一条 tRPC 连接；终端把宿主报的事实画出来，把人做的事送回去。

## 它是什么

本仓是 AI-Zen 的客户端仓。宿主（`@ai-zen/agents-host`）持有数据库、跑执行体 —— 模型调用、工具调用、subagent、能力容器都在那一侧；本客户端决定一次调用要做什么、把帧画成什么样，除了「上次连的是哪台」与界面语言之外不留自己的事实。

| | 宿主 | 本客户端 |
|---|---|---|
| 模型调用、工具调用、subagent | 有 | 没有 |
| 会话、消息、排队区、闸、交接、素材 | 在 `<数据根>/ai-zen.db` 里 | 从连接上读 |
| `<数据根>/config.json` | 由宿主读写 | 只通过 procedure 改 |
| 终端 | 不碰 | 全归它 |
| 拉起宿主 | 从不拉起自己 | 连接是本机而没人应答时拉起一台 |

分界一句话说清：此刻什么是事实由宿主定，一次调用做什么、一帧长什么样由客户端定。

## 装与跑

| 命令 | 做什么 |
|---|---|
| `pnpm install` | 装依赖 |
| `pnpm build` | 用 rolldown 打包进 `dist/` |
| `pnpm start` | 先 `pnpm build`，再跑 `node dist/index.js` |

`package.json` 声明了三个 bin 名 —— `ai`、`aiz`、`zen` —— 三者都指向 `dist/index.js`。

依赖图把本仓与旁边的 `agents` 仓绑在一起：`@ai-zen/agents-*` 是 `link:../agents/packages/*` 的 devDependency，连接层 `@ai-zen/agents-client` 是私有包、构建时内联进 `dist/`。宿主同样只在 `devDependencies` 里：它不是客户端的运行期依赖，运行期用 `npx` 现拉（见下）。

### 第一次跑

什么都没配过，所以客户端先问。既没有 `<数据根>/cli/connection.json`（这个文件只在人在屏上选过一台之后才写），也没有显式地址时，`ai` 摆出连接屏 —— 本机、远程、退出 —— 选之前一次 I/O 都不做。选本机交给拉起屏，选远程只会连。

宿主由 `npx` 起，所以本机第一次跑要下载它：

```bash
npx -y @ai-zen/agents-host@<range> serve --ai-zen-dir <数据根>
```

`<range>` 是这次构建所依据的 `@ai-zen/agents-host` semver 范围，构建时被写进 `dist/`。拉起屏一步一步说清走到哪了，一次一行，永不报百分比（npm 的输出不当协议解析）：

| 阶段 | 在等什么 |
|---|---|
| 解析版本 | npx 在那个范围里解析出要用哪一版 |
| 下载并安装 | npx 把它下载并装上 |
| 启动宿主 | 子进程已经起来，等它写发现文件并握手 |
| 已连上 | 不画：屏直接换成会话屏 |

拉不起来时屏上多一行子进程自己说的原因，并接受 `R` 再拉一次；`Esc` 与 `Ctrl+C` 杀掉那个子进程、回连接屏，不退出程序。宿主本来就在跑时一个阶段都不会来，拉起屏一个字节都不画。

连上之后，客户端进一个项目、开一段会话：

| 步骤 | 本机宿主 | 远端宿主 |
|---|---|---|
| 项目 | 运行 `ai` 时所在的目录，`workspace.list` 里已经有就复用 | 那台宿主上上次进入的那个，没有就弹选择器 |
| 会话 | 这个项目里上次打开的那一段，给了 `--new` 则一定是新的一段 | 同上 |
| 凭证 | 生效模型对应的端点没有 API Key 时，摆一块屏要它 | 同上 |

### 启动参数

| 参数 | 做什么 |
|---|---|
| `--server <url>` | 这次连这台宿主，不连本机；接受 `ws:` / `wss:` / `http:` / `https:`，也接受反向代理子路径 |
| `--new` | 跳过续接、开一段新会话（只在交互界面那条路上有效） |
| `--tui [提示词…]` | 强制进交互界面，后面的词作为首条消息自动发送（兜底钩子用它）；stdin 或 stdout 不是 TTY 时报错退出 |
| `--save` | 把一次 stdio 调用留成一段真会话（交互界面那条路忽略它） |
| `--server-status` | 把这个地址上宿主的状态按 JSON 打出来：答上了退出码 0，没答上 1；绝不拉起任何东西 |
| `hook install` / `hook uninstall` | 装 / 卸 shell 兜底钩子 |
| `-h`、`--help`、`-v`、`--version` | 用法与版本；单词形式 `ai help` / `ai version` 等价 |

`--` 之后一律当位置参数，于是提示词可以以 `-` 开头。

显式地址按 `--server`、`AI_ZEN_SERVER_URL`、发现文件的顺序取，它绝不会导致在本机拉起一台宿主：此处能拉起来的东西并不在那个地址上监听。这种宿主的凭证来自 `AI_ZEN_SERVER_TOKEN`，地址是回环时也可以来自 `<数据根>/run/token`。没有 `--token`：argv 会进 `ps` 输出与 shell 历史。

| 环境变量 | 含义 |
|---|---|
| `AI_ZEN_DIR` | 数据根（缺省 `~/.ai-zen`） |
| `AI_ZEN_SERVER_URL` | 与 `--server <url>` 同义；两个都给时以参数为准 |
| `AI_ZEN_SERVER_TOKEN` | 显式地址用的凭证 |

地址写错时在连接与拉起之前就停住，stderr 上一句人话，退出码 2。

## 两个模式

两个模式不混：一个进程只走其中一个。

| 模式 | 触发 | stdout | 退出码 |
|---|---|---|---|
| 交互界面 | 没有位置参数且 stdin 与 stdout 都是 TTY，或给了 `--tui` | 整个终端归界面 | 0 |
| 纯 stdio | 至少一个位置参数，或 stdin / stdout 不是 TTY | 只有答案正文 | 成功 0，调用失败 1，命令本身用错 2 |

纯 stdio 里参数是指令、stdin 是内容，两者都有时合成一条消息。日志、进度、通知一律走 stderr，这个模式不建日志文件。

一次 stdio 调用一次答案。缺省走 `session.transient`，带上运行时所在的目录：不建会话行，任何会话列表里都不会多出一条。给了 `--save` 则走 `session.create`、`agent.wake`、`agent.send`，会话 id 打在 stderr 上，这一次调用不挪「上次打开的那一段」的记忆。

| 情形 | 结果 |
|---|---|
| 没有配过宿主 | 退出码 2，一句指路（先跑一次 `ai`，或给 `--server`） |
| 没有输入（无参数、无管道） | 退出码 2，一句话 |
| 远端宿主上还没有进过项目 | 退出码 2，指到 `/ws` |
| 模型那条消息是失败 | 退出码 1 |
| 宿主发来一条提问 | 不作答：一次调用没有人可以问 |

`ai hook install` 往 `~/.bashrc` 或 `~/.zshrc` 里写一块，认哪个文件看 `$SHELL`（只支持 bash 与 zsh，其它一律退出码 1）。这一块定义 `command_not_found_handle`（bash）或 `command_not_found_handler`（zsh）为 `ai --tui --new "$@"`：敲错的命令于是进交互界面，作为首条消息发出去，并且是一段新会话。这一块由两行标记括起来，所以再跑一次 install 会就地换掉现有的那一块，`ai hook uninstall` 把找到的每一块都删掉。

## 命令

命令在输入行里以 `/` 开头打进去；输入行下面的菜单按前缀筛。名字、别名与说明出自同一张表，所以菜单、`/help` 与本页不会各说一套。

会话：

| 命令 | 别名 | 参数 | 做什么 |
|---|---|---|---|
| `/new` | | | 在当前项目里、用同一个助手另开一段会话；正在跑的那一段照旧跑 |
| `/load` | | `-a`、`--all` | 换一段已有的会话（`session.list`）；`--all` 跨项目 |
| `/sessions` | `/ps` | `-a`、`--all` | 列会话并切换；本进程挂着的那几段还会说忙闲、在忙什么、排队几条 |
| `/ws` | | `new [路径]`、`delete <名字或 ID>` | 列项目并切换（`/ws new` 在本机登记当前目录、在远端要一个绝对路径；`/ws delete` 删掉一个项目连同它名下的会话） |
| `/pin` | | `on`、`off` | 置顶 / 取消置顶这一段（`session.pin`） |
| `/back` | `/revert` | | 撤回到你的某条消息之前（`session.rewind`）；撤掉的文字与素材回到输入框 |
| `/rename` | `/save` | `<名字>` | 给这一段改名（`session.rename`） |
| `/editor` | | | 用 `$EDITOR`、`$VISUAL` 或平台缺省编辑器写这一条消息 |
| `/clear` | | | 只清屏，上下文一个字不动 |
| `/free` | | | 清空排队区（`agent.clearInbox`），并说清掉了几条 |
| `/delete` | | | 删掉这一段会话（`session.remove`）；确认那一句先说清消息条数与素材份数 |
| `/kill` | | `[ID 或名字]` | 杀掉一段会话的执行体（`agent.kill`）；会话行与历史留着 |
| `/exit` | `/quit` | | 退出客户端；宿主继续跑 |

配置：

| 命令 | 别名 | 参数 | 做什么 |
|---|---|---|---|
| `/config` | | | 打开配置中心 |
| `/model` | | `[<id>]`、`-a`/`--agent [<id>]`、`-g`/`--global [<id>]` | 换模型：这一段会话、助手定义、或全局兜底 |
| `/think` | `/effort` | `[档位]`、`-a`/`--agent [档位]` | 换思考强度：这一段会话或助手定义 |
| `/agent` | | `[id]` | 选默认助手；只对以后新开的会话生效 |
| `/mcp` | | `[user\|workspace]` | 进配置中心的 MCP 屏，落在那一层 |
| `/key` | | | 设当前端点的 API Key |
| `/lang` | | `[zh\|en]` | 换语言：宿主渲染的句子读 `config.language`，界面读本机偏好；不带参数在两门之间切 |
| `/reload` | | | 让宿主重新发现工具、skill、MCP 服务器与 subagent（`scope.reload`），再把这一段的事实重取一次 |

交接：

| 命令 | 参数 | 做什么 |
|---|---|---|
| `/handoff` | `[self\|summary]` | 只写一份交接文档（`handoff.start`，`kind: "document"`）；不给参数时先问一句谁来写 |
| `/migrate` | `[self\|summary]` | 写完文档当场换手（`kind: "swap"`），旧记忆成为一段已存档会话；它不问 |

宿主：

| 命令 | 做什么 |
|---|---|
| `/upgrade` | 从 registry 上取 `@ai-zen/agents-host` 各 dist-tag 里 semver 最高的一版，确认一次后把版本交给宿主（`host.upgrade`）：宿主先验这一版拿得到、记下下次该拉哪一版、再以升级为由退出；客户端回连接屏 |
| `/shutdown` | 关掉宿主（`host.shutdown`）；一台机器一个宿主，所以这一下会踢掉同一台机器上的其它客户端，之后客户端回连接屏 |
| `/help` | 列出命令与各自那一句说明 |

`/handoff self` 由这一段会话自己的执行体写文档，`summary` 另起一个只干这一件事的一次性执行体去写。

上下文到了交接线，或者一个不可撤销的动作之前，宿主会发一条提问。客户端用宿主给的原话与候选把这一问画出来，把人选的那一格送回去（`question.answer`）；不作答就让它挂着，宿主随后拒绝发送。

## 界面

空会话时转录顶部是品牌块 —— logo、标语、客户端与 SDK / core 的版本 —— 它是转录的普通内容，会随转录滚走，滚回来还能看到。

布局吸底。自下而上依次是：状态栏、输入行、分割线、排队区、阶段行、命令菜单、待发图片行、通知栏、subagent 页签。分割线以上那几块只在有话要说时出现，剩下的高度全给转录。

状态栏由五块组成，每一块都在画这一帧时从会话上现取：

| 块 | 内容 |
|---|---|
| 身份 | 模型 id、助手名、思考强度 |
| 四件事 | 忙或闲；停机、输出闸关、输入闸关各自在不是常态时出现 |
| 用量 | 这一次回答用的 token 与全部回答的 token 合计，由客户端从每条消息的 `usage` 上算 |
| 速率 | 生成中是实时估算，结束后是这一次回答的平均 |
| 快捷键 | 界面自己的提示那一行 |

块是折行的单位：放不下就整块挪到下一行，空块不占宽度。

阶段行在分割线之上，执行体手上有活时才有，说的是客户端从手上的事实里读得出的那一档：正在交接、在队里等、连接中、等首字、在想、调工具、等工具回来、在输出。调工具与等工具那两档会念出工具名，几件并行时只念还在跑的那几个。

有 subagent 时转录下面多一行页签。每个页签前面的 `◈` 说的是状态 —— 跑起来时闪、散场是绿、失败是红、被叫停是淡、挂着不动是暗 —— 输入框为空时按 `←` / `→` 就换一段转录看。

通知栏是通知唯一上屏的地方，它们永远不进消息，于是永远到不了模型。三档语气：info、warning、error（宿主那四档折成这三档）。栏位留最近 4 条、最多 8 行，放不下时从最早的那一条整条让位。两个清空入口：`Alt+X` 清这一段会话的（本地队列加上带这个会话 id 的 `notice.clear`），`Alt+Shift+X` 先问一次、再把全部清掉 —— 全局通知与别的会话的也在其中。

转录里的图片一律是占位，终端画不了内联图。`Ctrl+O` 列出这一段里还带着素材 id 的那些图，选中一张就去取字节（`asset.get`）、写一个临时文件、交给本机默认程序（`open`、`xdg-open` 或 `cmd /c start`）；三步各自报自己那一种失败。

`Ctrl+V`（终端报得上来的地方 `Cmd+V` 也行）先问系统剪贴板有没有图片 —— macOS 走 `osascript`，Linux 走 `wl-paste` 或 `xclip`，Windows 走 PowerShell —— 有就把它挂到接下来那条消息上；剪贴板里没有图片时按普通粘贴把文字插到光标处。剪贴板文本超过 256 KB 时拒收，不截断。挂上的图片随消息经 `asset.upload` 上去；放不放得下是宿主的规矩，它的拒绝原话上屏。

`@` 补全文件路径：候选是宿主为这个项目列出的相对路径（`workspace.files`），插进草稿的是路径本身，所以消息仍是普通文本，文件由模型自己用工具去读。

请求在途时照样能打字。这时发出去的消息交给宿主，由它放进排队区；分割线之上的排队区显示还在等的那几条，阶段行也会说这件事。

## 配置面

`/config` 打开配置中心。一个主题一块屏，每一格改完就写，没有保存键，也没有会丢的草稿：

| 屏 | 改什么 |
|---|---|
| 端点 | 名字、base URL、API Key、说明；增与删 |
| 模型 | 名字、端点、模型名、思考档位表、交接阈值与防护阈值、能不能看图、说明；增、删、恢复出厂那一条 |
| 图片模型 | 名字、端点、模型名、缺省尺寸与质量、说明 |
| MCP 服务器 | 一次一层（用户级或项目级）：传输方式、命令、参数、环境变量、URL、请求头、启停、说明 |
| 助手 | 助手与 subagent：名字、说明、模型、思考档位、提示词、权限 |
| 缺省项 | 默认助手、兜底模型、迁移模型、默认图片模型、命名模型、中断后保留输出、中断后工具调用怎么处理、自动命名 |
| 工具输出上限 | 留在上下文里的工具输出字符数 |

每一次改动是一次 procedure 调用，回来的都是整份配置，所以屏上接着显示的与宿主手里的是同一份。两个中断开关是 `abortedMessageStrategy`（把中断前那半条留在上下文里，或丢掉）与 `abortedToolRoundStrategy`（整批工具调用留着、给没跑完的补一个理由，或整批丢掉）的用户可见形态。

模型来自三级：会话行、助手定义、`config.json` 里的兜底。`/model` 不带级别参数写会话行，`-a` 写助手定义，`-g` 写兜底。手上有活的会话换模型或换思考档位会被宿主拒，所以客户端先问一句要不要现在试。

模型与图片模型上有 `custom` 这一格。没标 `custom: true` 的条目属于出厂清单，宿主每次读配置时都会按出厂清单换掉；恢复出厂会把这一格重新清掉。端点从不这样托管。

## 本机留了什么

数据根（`AI_ZEN_DIR`，缺省 `~/.ai-zen`）下属于客户端的是四个文件与它自己的日志目录，其余都是宿主的。

| 路径 | 内容 |
|---|---|
| `cli/connection.json` | 连接屏上选过的那一台；只有人在屏上选了才写 |
| `cli/last-workspace.json` | 上次进入的项目，每台宿主一格 |
| `cli/last-session.json` | 上次打开的那段会话，每个项目一格 |
| `cli/preferences.json` | 界面语言（`AIZ_PREFERENCES_FILE` 可改路径） |
| `logs/cli/cli.log` | 客户端日志，单份 2 MB、留两份；warn 与 error 同时上通知栏 |
| `logs/cli/launch.log` | 本客户端拉起宿主那一次的子进程输出，每次拉起重写 |
| `logs/cli/keys.log` | 按键诊断，只在 `AIZ_DEBUG_KEYS=1` 时写（`AIZ_KEYS_FILE` 可改路径） |

同一个根下属于宿主的那一侧：`ai-zen.db`（库）、`config.json`（配置）、`run/host.json`（宿主服务在哪个端口）、`run/token`（本机凭证）、`run/next-version.json`（下次该拉起哪一版）、`logs/host.log`。

| 门禁 | 命令 | 管什么 |

`pnpm test:all` 把六道门禁串起来跑（类型、格式、单元、构建、产物图、端到端）。端到端那一套需要 `dist/` 与旁边 `agents` 仓构建出来的宿主（`../agents/packages/host/dist/cli.js`）；本机拉起那条路走一个只会转发的假 `npx`，所以不联网。不要把它与别的会起真宿主的测试同时跑。
