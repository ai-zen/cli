# 还没做的事

每条写清三样：**现在是什么行为、要变成什么行为、怎么算做完了**。写不全就说明还没想清。
做掉之后从这里删掉，不许长期躺着。

---

## 1. 注释的专项治理：语气向「客服 / 技术人员」看齐

- **现在是什么行为**：上一轮把**界面上给人看的文案**（`src/i18n/zh*.ts` 两个词典 + 三处硬编码）
  按「名词化 + 结果 + 括号只放事实」重写了一遍，并用 `dict-guard.test.ts` 的三道机械守卫钉住
  （禁用词黑名单、通知出口不许硬编码、键集合与死词条）。**代码注释不在这轮范围内**，它们仍是
  原来那套语气：把引擎当人写（「它先确认这一版拿得到」「这辈子都在等」「死在半路」「白烧一次
  全量输入」「顺手关掉」「喂给队列」「别急着投」），一句话里混着事实、比喻与自我辩解。
  读者是改代码的人，但语气仍是口语，与产品的技术腔不一致。
- **要变成什么行为**：注释按同一套口径重写 —— 陈述句、名词化、先事实后理由；比喻与拟人退场
  （「它拿得到」→「宿主能解析到该版本」）；一句话只讲一件事，允许长，但不允许含糊。
  分档处理，不搞一次性大扫除：
  1. `src/tui/**`（用户能摸到的屏，注释里最多解释「为什么这样摆」）；
  2. `src/session*.ts` / `src/commands/**`（状态机与命令层，注释里解释「为什么是这个次序」）；
  3. `packages/*/src`（agents 仓：core / sdk / host 的机制注释，最密也最值钱）。
- **怎么算做完了**：
  - 每一档收尾时，抽样 40 条注释做「口语词扫描」：禁用词表（`不收话` / `叫起来` / `这一批` /
    `换家` / `撑爆` / `白的` / `顺手` / `喂` / `死` / `一把` 一类）零命中；
  - 抽 10 条注释请人只读注释、不看代码复述「这段为什么这么写」，能复述即为合格；
  - 不改变任何行为：整轮只动注释，`tsc` / `vitest` / `e2e` 全程不红（这是「只动注释」的最硬证据）。
  - 有一个现成的抓手：`dict-guard.test.ts` 的禁用词表可以直接扩成「注释扫描」的同一份黑名单，
    免得到时候两套词表各说各话。
