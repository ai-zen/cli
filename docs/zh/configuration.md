# 配置

配置分两处，边界是「谁需要读它」：

| 文件 | 内容 | 谁写 |
|---|---|---|
| `<数据根>/config.json` | 端点、模型、图片模型、助手定义、子代理、MCP 服务器引用 | 客户端通过宿主的接口写 |
| `<数据根>/cli/preferences.json` | 界面语言 | 只有 CLI 自己 |

界面语言不进 `config.json`：那个文件的类型是跨端共享的配置，往里塞 CLI 的偏好，桌面端读到既不理解，回写时还可能把它丢掉。

## 配置中心

`/config` 打开配置中心，四类东西都在这里：

| 分组 | 可改的项 |
|---|---|
| 端点 | 名称、Base URL、API Key、说明 |
| 模型 | 端点、发给端点的模型名、思考策略、交接阈值、阻断阈值、是否支持图片 |
| 图片模型 | 端点、模型名、默认尺寸、默认质量 |
| 助手定义 | 名称、说明、系统提示词、绑定模型、四维权限；子代理另有函数说明与参数 schema |
| MCP 服务器 | 传输方式、命令与参数、环境变量、请求头、启用状态 |

长文本字段（系统提示词、参数 schema）按 `Enter` 打开外部编辑器写。保存前后端会校验：名称不能为空、Base URL 必须以 `http://` 或 `https://` 开头、API Key 不能为空、参数 schema 必须是 JSON 对象。

## 模型的三级解析

一段会话用哪个模型，按三级取，取到就停：

1. 会话行的 `modelId`（`/model` 的「本次会话」）
2. 助手定义的 `modelId`（`/model` 的「助手定义」）
3. `config.json` 的 `defaultModel`（`/model` 的「全局」）

三级都取不到时报错，错误里指明是哪份定义没有绑定模型。不会静默挑一个出厂模型顶上——那会变成界面写着 A、请求与账单落在 B。

参数跟着模型来自哪一级走：会话级换过模型时，不再合并助手定义上的 `modelParams`。旧参数配给新模型，端点会直接拒。

## 思考强度

`/think` 的档位不是写死的一组，而是读端点的思考策略表 `<数据根>/reasoning-presets.json`。表里有哪些档就能选哪些：

- 表里有 `off` 才能关思考。某些模型强制思考且没有关闭参数，那就没有关闭这一档
- 选「跟随模型默认」等于清掉这一层参数，回到模型定义的 `defaultParams`
- 每档对应一组请求参数补丁。各家协议差异（`reasoning_effort` 与 `thinking`）关在表里，客户端只负责把选中的那一档写进配置

运行期不做档位推导：写进配置就是展开后的具体参数，请求时只做一次浅合并。

## 交接阈值

两条阈值可以写在模型定义上，也可以被会话行覆盖（`/config` 里改模型时是前者，会话级覆盖由交接相关的入口写）：

| 阈值 | 含义 |
|---|---|
| 交接阈值（`handoff`） | 软线。越过之后 agent 空闲时交接 |
| 阻断阈值（`guard`） | 硬线。每次请求前比对，越线就拒掉这一次请求 |

出厂口径是窗口的 40% 与 80%。两个都是绝对值，写多少就是多少。

## API Key

`/key` 就地设某个端点的密钥。密钥明文存在 `config.json` 里，文件权限由使用者保证；它不是凭证（客户端连宿主用的那串）——那串在宿主那一侧，见 `/upgrade` 与宿主文档。

## MCP 服务器

`/mcp` 管增删、编辑与启停。写进哪个文件取决于服务器原来写在哪一层：

| 层 | 文件 | 能否从这里改 |
|---|---|---|
| 项目宿主目录 | `<项目>/.ai-zen/mcp.json` | 能 |
| 用户级 | `<数据根>/mcp.json` | 能 |
| 项目根、项目共用目录、主目录共用 | 各处的 `mcp.json` | 只读：那是别人的文件 |

改名、改传输方式、停用都在这一层完成；停用写的是那一条的 `disabled`，不是删掉它——删掉会让远层同名定义重新生效，而你的意思是「这条不要」。

改完不必重启：`/reload`，或等宿主按 `autoRefreshTools` 下次刷新。

## 语言

`/lang` 切换界面语言，写进 `<数据根>/cli/preferences.json`。宿主的语言是另一件事：它写在 `config.json` 的 `language` 上，影响宿主产生的文本（通知、题、错误消息）。客户端连上之后会把自己这一侧的语言同步给宿主，所以两边通常一致。

## 默认助手

`/agent` 设的是「新会话默认用哪份助手定义」。它不动当前这段会话用的定义，也不动模型：定义里绑的模型是二级解析，与当前会话的模型覆盖是两回事。
