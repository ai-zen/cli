# 配置

## 配置存在宿主那边

配置是数据根下的 `config.json`（数据根由 `AI_ZEN_DIR` 给，缺省 `~/.ai-zen`），由宿主读写。客户端不在本地拼一份「整个配置」，也不写这个文件：它只经 procedure 读写 —— 读一次 `config.get`（配置加思考档位表一起给回），每一次改动发一条写调用（`config.defaults.update`、`config.update`、`config.endpoints.*`、`config.models.*`、`config.imageModels.*`、`config.mcp.update`、`config.agents.update` 等），回来的都是改完之后的整份配置。

所以屏上接着显示的那份与宿主手里的是同一份。写成功就算生效，没有「要不要重启才生效」那一格。

## 配置中心

`/config` 打开配置中心。一个主题一块屏，列表第一项是新建（MCP 那一屏还多一个切层的项），选中一条进详情屏就地编辑：

| 屏              | 改什么                                                                                                          |
| --------------- | --------------------------------------------------------------------------------------------------------------- |
| 端点            | 名字、Base URL、API Key、说明；增与删                                                                           |
| 模型            | 名字、端点、模型名、思考档位表、交接阈值与防护阈值、能不能看图、说明；增、删、恢复出厂那一条                    |
| 图片模型        | 名字、端点、模型名、缺省尺寸与质量、说明；增、删、恢复出厂那一条                                                |
| MCP 服务器      | 一次一层（用户级或项目级）：名字、传输方式（stdio / http / sse）、命令、参数、环境变量、URL、请求头、启停、说明 |
| AgentDefinition | AgentDefinition 与 subagent：名字、说明、模型、思考档位、提示词、权限四维（工具、skill、MCP、subagent）         |
| 缺省项          | 见下一节                                                                                                        |
| 工具输出上限    | 留在上下文里的工具输出字符数                                                                                    |

规则只有一条：改一格写一格。没有全局保存键，也没有会丢的草稿 —— 一个字段改完就发一次写调用，回来的整份配置立刻是屏上的下一帧。

四处细节：

- 删端点之前先摆出还有谁指着它（模型、图片模型的名字一个不少）；宿主拒删时把它的原话上屏。
- 删模型之前说清三个默认项里哪几个指着它、会改指到哪一条（同端点剩下的第一条），或者被清空。
- 新建模型要当场给两条阈值（交接线与防护线），宿主不补这两格，屏上给的是一个能就地改的起点。
- 提示词、函数说明、参数 schema 这类多行内容按 `Enter` 调起本机编辑器；内容没改就不写盘。

关掉配置中心时，这一次改过的那几条合成一条通知，说清改了什么；有改动时这一段会话还会把手里的事实重取一次（模型、思考档位、状态栏那几块）。

## 缺省项

| 项                     | 是什么                                                                         |
| ---------------------- | ------------------------------------------------------------------------------ |
| 默认 AgentDefinition   | 以后新开的会话用哪个 AgentDefinition；已经开着的会话不受影响                   |
| 兜底模型               | AgentDefinition 没绑模型时用哪一条                                             |
| 迁移模型               | 交接那一趟用哪一条                                                             |
| 默认图片模型           | 生图默认用哪一条                                                               |
| 命名模型               | 自动起名用哪一条                                                               |
| 中断后保留输出         | `abortedMessageStrategy`：中断前那半条（思考与正文）留在上下文里，或丢掉       |
| 中断后工具调用怎么处理 | `abortedToolRoundStrategy`：整批工具调用留着、给没跑完的补一个理由，或整批丢掉 |
| 自动命名               | 开 / 关：会话第一次闲下来时要不要让宿主起一个名字                              |

前五项可以「不设置」，清掉之后没有指向；后三项是固定几档，没有空档。两个中断项是那两个字段的用户可见形态，改完当场对活着的 Agent 生效；自动命名改完不重建任何 Agent，下一次变闲就是新值。

工具输出上限不挂在 Agent 上：Scope 在工具调用那一刻现读它，改完不必重建 Agent。

## 出厂托管

模型与图片模型上有一格 `custom`。没标 `custom: true` 的那一条属于出厂清单，宿主每次读配置时都会按出厂清单换掉；编辑出场托管的那一条时宿主会自动把它标成自定义。

模型与图片模型的详情屏有「恢复出厂」：把这一条换回出厂清单里同 id 的那一条，并重新归出厂托管。端点从不这样托管，增删改都由人说了算。

## 模型来自三级

| 级              | 写在哪                                    | 谁写             |
| --------------- | ----------------------------------------- | ---------------- |
| 这一段会话      | 会话行上的 `modelId`                      | `/model <id>`    |
| AgentDefinition | 定义的 `modelId`                          | `/model -a <id>` |
| 全局兜底        | `config.json` 的 `defaultModelDefinition` | `/model -g <id>` |

会话级的覆盖最先生效，其次是 AgentDefinition，最后才是兜底。状态栏上那个模型 id 是宿主按这一套解析出来的结果，客户端不自己推。

思考强度有两档可写：这一段会话（`session.updateThinkingLevel`）与 AgentDefinition（`config.agents.update` 的 `modelParams`）。可选的档位由模型引用的那张档位表给，客户端只查它、不另抄一份。

其余几条命令各自只写一格：`/agent` 写默认 AgentDefinition，`/key` 写当前端点的 API Key，`/mcp` 进 MCP 那两层的屏，`/lang` 写 `config.language` 与本机偏好，`/reload` 不改配置，它让宿主按磁盘上的配置重刷 Scope。

## 本机留下的那几份

数据根下属于客户端的是四份小文件与它自己的日志目录，其余都是宿主的。

| 路径                      | 内容                                                               |
| ------------------------- | ------------------------------------------------------------------ |
| `cli/connection.json`     | 连接屏上选过的那一台；只有人在屏上选了才写                         |
| `cli/last-workspace.json` | 上次进入的项目，每台宿主一格                                       |
| `cli/last-session.json`   | 上次打开的那段会话，每个项目一格                                   |
| `cli/preferences.json`    | 界面语言（`AIZ_PREFERENCES_FILE` 可改路径）                        |
| `logs/cli/cli.log`        | 客户端日志，单份 2 MB、留两份；warn 与 error 同时上通知栏          |
| `logs/cli/launch.log`     | 本客户端拉起宿主那一次的子进程输出，每次拉起重写                   |
| `logs/cli/keys.log`       | 按键诊断，只在 `AIZ_DEBUG_KEYS=1` 时写（`AIZ_KEYS_FILE` 可改路径） |

这几个文件都是缓存：读不出来的那份不写回，按没有记录继续，磁盘上一个字节都不动。
