# 快速开始

## 装与构建

本仓用 pnpm 管依赖，构建产物是一个打包好的 `dist/`：

| 命令           | 做什么                                     |
| -------------- | ------------------------------------------ |
| `pnpm install` | 装依赖                                     |
| `pnpm build`   | 用 rolldown 把源码与连接层一起打进 `dist/` |
| `pnpm start`   | 先 `pnpm build`，再跑 `node dist/index.js` |

`package.json` 声明三个 bin 名 —— `ai`、`aiz`、`zen` —— 三者都指向 `dist/index.js`。把包按本机全局装上（`npm install -g .`）之后，这三个名字都能直接敲。

宿主不在运行期依赖里：`@ai-zen/agents-host` 只住在 `devDependencies` 里当版本范围的声明，运行期由 `npx` 现拉（见下）；`@ai-zen/agents-client` 是私有包、构建时内联进 `dist/`。

## 启动参数

| 参数                              | 做什么                                                                            |
| --------------------------------- | --------------------------------------------------------------------------------- |
| `--server <url>`                  | 这次连这台宿主，不连本机                                                          |
| `--new`                           | 跳过续接、开一段新会话（只在交互界面那条路上有效）                                |
| `--tui [提示词…]`                 | 强制进交互界面，后面的词作为首条消息自动发送；stdin 或 stdout 不是 TTY 时报错退出 |
| `--save`                          | 把一次 stdio 调用留成一段真会话（交互界面那条路忽略它）                           |
| `--server-status`                 | 把这个地址上宿主的状态按 JSON 打出来：答上了退出码 0，没答上 1；绝不拉起任何东西  |
| `hook install` / `hook uninstall` | 装 / 卸 shell 兜底钩子                                                            |
| `-h`、`--help`、`-v`、`--version` | 用法与版本；单词形式 `ai help` / `ai version` 等价                                |

`--` 之后一律当位置参数，于是提示词可以以 `-` 开头。

## 第一次跑

什么都没配过，所以客户端先问。既没有 `<数据根>/cli/connection.json`（这个文件只在人在屏上选过一台之后才写），也没有显式地址时，`ai` 摆出连接屏：本机、远程、退出。选之前一次 I/O 都不做。

选本机交给拉起屏。宿主由 `npx` 起，所以本机第一次跑要下载它：

```bash
npx -y @ai-zen/agents-host@<range> serve --ai-zen-dir <数据根>
```

`<range>` 是这次构建所依据的 `@ai-zen/agents-host` semver 范围，构建时写进 `dist/`；`<数据根>` 是 `AI_ZEN_DIR`，缺省 `~/.ai-zen`。

拉起屏一步一步说清走到哪了，一次一行，永不报百分比（npm 的输出不当协议解析）：

| 阶段       | 在等什么                             |
| ---------- | ------------------------------------ |
| 解析版本   | npx 在那个范围里解析出要用哪一版     |
| 下载并安装 | npx 把它下载并装上                   |
| 启动宿主   | 子进程已经起来，等它写发现文件并握手 |
| 已连上     | 不画：屏直接换成会话屏               |

拉不起来时屏上多一行子进程自己说的原因，并接受 `R` 再拉一次；`Esc` 与 `Ctrl+C` 杀掉那个子进程、回连接屏，不退出程序。宿主本来就在跑时一个阶段都不会来，拉起屏一个字节都不画。

## 连远端

远端那台宿主上没有人替你启动，所以只连不拉：

| 写法                | 结果                                           |
| ------------------- | ---------------------------------------------- |
| `ai --server <url>` | 这次连这台宿主，不连本机                       |
| `AI_ZEN_SERVER_URL` | 与 `--server <url>` 同义；两个都给时以参数为准 |
| 连接屏的「远程」    | 填地址与访问令牌；令牌留空表示用本机宿主的令牌 |

地址接受 `ws:`、`wss:`、`http:`、`https:`，也接受反向代理子路径；没写协议前缀的 `host:port` 按 `ws://` 补。地址写错时在连接与拉起之前就停住，stderr 上一句人话，退出码 2。

| 环境变量              | 含义                       |
| --------------------- | -------------------------- |
| `AI_ZEN_DIR`          | 数据根（缺省 `~/.ai-zen`） |
| `AI_ZEN_SERVER_URL`   | 与 `--server <url>` 同义   |
| `AI_ZEN_SERVER_TOKEN` | 显式地址用的凭证           |

没有 `--token`：argv 会进 `ps` 输出与 shell 历史。凭证的完整来历见[宿主](./host.md)。

诊断用 `ai --server-status`：把这个地址上宿主的状态按 JSON 打出来，答上了退出码 0，没答上 1。它绝不拉起任何东西。

## 进项目、开会话

连上之后，客户端进一个项目、开一段会话：

| 步骤 | 本机宿主                                                  | 远端宿主                                 |
| ---- | --------------------------------------------------------- | ---------------------------------------- |
| 项目 | 运行 `ai` 时所在的目录，`workspace.list` 里已经有就复用   | 那台宿主上上次进入的那个，没有就摆选择器 |
| 会话 | 这个项目里上次打开的那一段，给了 `--new` 则一定是新的一段 | 同上                                     |
| 凭证 | 生效模型对应的端点没有 API Key 时，摆一块屏要它           | 同上                                     |

## 说第一句话

光标在输入行里，打字，`Enter` 发送。回答在转录里逐字出现，状态栏与阶段行说清此刻在做什么（见[界面](./interface.md)）。

几件够用的事：

- 以 `/` 开头会列出命令并按前缀筛，`/help` 列全部（见[命令](./commands.md)）。
- `@` 补全这个项目的文件路径；插进去的是路径本身，所以消息仍是普通文本，文件由模型自己用工具去读。
- `Ctrl+V` 先问剪贴板有没有图片，有就挂到这条消息上；剪贴板里没有图片就按普通粘贴插文字。
- 请求还在途时照样能打字：这一句交给宿主放进排队区，排队区显示在分割线之上。

## 退出

| 做法                    | 结果       |
| ----------------------- | ---------- |
| `/exit` 或 `/quit`      | 退出客户端 |
| 输入行为空时按 `Ctrl+C` | 退出客户端 |
| 连按两次 `Ctrl+D`       | 退出客户端 |

退出只收掉这一个进程：宿主继续跑，正在跑的那一段在宿主那边照旧。要把宿主也关掉是 `/shutdown`（见[宿主](./host.md)）。

## 带参数或走管道时

`ai` 只在没有位置参数、且 stdin 与 stdout 都是 TTY 时进交互界面。带参数，或者 stdin / stdout 不是 TTY，则走纯 stdio：一次调用一条消息、一个答案，stdout 上只有答案正文，日志与进度一律走 stderr，这个模式不建日志文件。

```bash
ai 你好，请介绍一下你自己。
cat README.md | ai "用三句话总结"
```

缺省走 `runtime.agent.runOnce`，带上运行时所在的目录：不建会话行，任何会话列表里都不会多出一条。给了 `--save` 则建一段真会话，会话 id 打在 stderr 上。退出码：成功 0，调用失败 1，命令本身用错 2。
