# 快速开始

`@ai-zen/cli` 是 AI-Zen 宿主的终端客户端。它自己不调用模型，也不存会话：会话、历史、模型配置都在宿主那一侧，客户端只负责连接、渲染与发送命令。

## 前提

- Node.js 24 及以上
- 一台可达的宿主（`@ai-zen/agents-host`），本机或远端
- 一个 OpenAI 兼容端点的密钥（配置在宿主那一侧）

## 安装与启动

```bash
npm i -g @ai-zen/cli
ai
```

`bin` 里登记了三个等价的名字：`ai`、`aiz`、`zen`。从源码构建：`cd cli && npm run build`，入口是 `dist/index.js`。

启动后先到连接屏：

| 项 | 做什么 |
|---|---|
| 本机 | 在本机启动宿主并连接。宿主没装时先下载，必要时先拉起，界面上有下载与启动的进度 |
| 远程 | 填写宿主地址与访问令牌 |

`↑↓` 选择，`Enter` 确认，`Esc` 退出。地址可以写成 `wss://example.com/ai-zen` 或 `10.0.0.5:8790`；不写协议前缀时按 `ws://` 处理。令牌留空表示用本机宿主的令牌（启动宿主时自动生成，写在 `<数据根>/run/token`）。

显式指定连接目标可以跳过这一步：

```bash
ai --server ws://192.168.1.10:8790
```

## 两种模式

同一个进程只走其中一条：

| 调用方式 | 模式 |
|---|---|
| 带位置参数，或 stdin / stdout 不是 TTY | 纯 stdio：一次性调用，只把助手最终的文本写进 stdout，日志与进度走 stderr |
| 无参数且 stdin / stdout 都是 TTY，或带 `--tui` | 交互界面 |

```bash
ai "这个仓库用了哪些构建脚本"     # 一次性调用，不落库
ai --save "看完 src 后总结一下"    # 一次性调用，但写成一段真会话
ai --new                          # 进界面，开一段新会话，不续接这个目录上一次的
```

`--tui` 明确要求交互界面；终端不支持时报错退出，不降级成 stdio。

## 进入界面之后

底部输入框里直接打字，`Enter` 发送，`Ctrl+J` 换行，`/` 打开命令菜单，`@` 打开文件补全，`PgUp` 回看历史。

一段会话对应宿主上的一个工作区目录。第一次进入一个目录时，界面会让你先选一个工作区——工作区就是会话干活的那个目录，`@` 补全与工具的相对路径都以它为准。

## 退出

| 动作 | 结果 |
|---|---|
| `Ctrl+D` 两次 | 退出程序，宿主继续运行 |
| `/exit`（别名 `/quit`） | 同上 |
| `/shutdown` | 关闭宿主，回到连接屏 |

退出程序不影响会话：历史在宿主那一侧，下次进同一个目录会续接上一次打开的会话。

## 退出码

| 码 | 含义 |
|---|---|
| `0` | 成功（含 `--help`、`--version`、`hook` 的用法提示、`--server-status` 在跑） |
| `1` | 已经跑起来之后的失败：模型报错、`--server-status` 发现没在跑、`hook` 的子动作不认识 |
| `2` | 命令本身用错：`--tui` 但终端不是 TTY、`--server` 的地址拼错、纯 stdio 模式没有输入 |

脚本依赖这条分界：`1` 留给运行期失败，`2` 留给调用方式错误。
