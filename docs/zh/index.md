# AI-Zen CLI

`@ai-zen/cli` 是 AI-Zen 宿主（`@ai-zen/agents-host`）的终端客户端。一条 WebSocket 上走一条 tRPC 连接：会话、消息、排队区、`isInputPaused` / `isOutputPaused`、交接、Asset 都在宿主那边，终端把宿主报的事实画出来，把人做的事送回去。

## 与宿主的分工

|                                                                     | 宿主                       | 本客户端                       |
| ------------------------------------------------------------------- | -------------------------- | ------------------------------ |
| 模型调用、工具调用、subagent                                        | 有                         | 没有                           |
| 会话、消息、排队区、`isInputPaused` / `isOutputPaused`、交接、Asset | 在 `<数据根>/ai-zen.db` 里 | 从连接上读                     |
| `<数据根>/config.json`                                              | 由宿主读写                 | 只通过 procedure 改            |
| 终端                                                                | 不碰                       | 全归它                         |
| 拉起宿主                                                            | 从不拉起自己               | 连接是本机而没人应答时拉起一台 |

分界一句话说清：此刻什么是事实由宿主定，一次调用做什么、一帧长什么样由客户端定。

于是这个仓里没有工具实现、没有 skill 发现、没有 MCP 连接，也没有模型请求。工具面、Scope 与交接两档都是宿主与 SDK 的能力，客户端留下的只是命令入口（见[命令](./commands.md)）；能力本身在 `@ai-zen/agents-host` 与 SDK 那一侧的文档里讲。

## 客户端自己管什么

两件事归客户端，因为它们是这一次调用的事：一条斜杠命令要做什么（[命令](./commands.md)），一帧长什么样（[界面](./interface.md)）。

它在本机只留四份小文件与自己的日志目录 —— 上次在连接屏上选的那台宿主、上次进入的项目、上次打开的会话、界面语言；会话与配置一概不留。那几份的路径列在[配置](./configuration.md)末尾。
