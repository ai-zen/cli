# 管道与钩子

除了交互界面，同一个可执行文件还有一条不画界面的路：一次性调用。它面向脚本、编辑器插件与 shell 管道。

## 什么时候走这条路

判定只有一条规则，两个条件任一成立即走：

- 带了位置参数
- stdin 或 stdout 不是 TTY

无参数且两端都是 TTY 时进交互界面。`--tui` 是显式覆盖：要求界面但终端不支持时报错退出，不降级成管道。

## 输出契约

| 流 | 内容 |
|---|---|
| stdout | 只有助手最终的文本。零 ANSI、零 emoji 前缀、零转圈 |
| stderr | 日志、进度、通知、`--save` 写出的会话 id |

因此 `ai "…" > answer.txt` 拿到的是干净的结果，诊断信息一个字节都不混进去。

## 两种落点

```bash
ai "这段报错什么意思"              # 一次性：不属于任何会话，不落库，不进会话列表
ai --save "把这段配置整理成 yaml"    # 写成一段真会话：先建行、再唤醒、再发送，然后跟读到结束
```

默认那次不落库：本机这条路上连项目行都不建。远端宿主那条需要知道在哪个目录上干活——一次性会话也要一个目录去装配能力，而目录属于项目行。所以远端且还没有项目时，这条命令会先让你在交互界面里挑一个目录。

`--save` 会在 stderr 打出新会话的 id。它不改变「上次打开的会话」那一条记忆：脚本调用不该把交互界面的续接位置挪走。

## 没有人可以回答

一次性调用没有可交互的界面，所以这条路上不挂题板：宿主发来的题（交接选哪种方式、MCP 服务器要求填表）会一直挂着，而不是被随便选一个。要那些功能，用交互界面。

## 退出码

| 码 | 含义 |
|---|---|
| `0` | 成功 |
| `1` | 模型报错、宿主拒绝、连接失败 |
| `2` | 调用方式错误：没有输入、`--server` 地址拼错 |

## shell 钩子

把「敲错命令」接成「问 AI」。安装：

```bash
ai hook install      # 往 rc 文件写一段 command_not_found_* 钩子
ai hook uninstall    # 删掉那一段
ai hook              # 只看用法
```

写到哪儿取决于 `$SHELL`：含 `zsh` 写 `~/.zshrc` 的 `command_not_found_handler`，含 `bash` 写 `~/.bashrc` 的 `command_not_found_handle`；其他 shell 不支持，命令会直接说清。

钩子执行的是 `ai --tui --new "$@"`，不是管道：

- `--tui`：敲错命令的人坐在终端前，要能看到对话、能追问；管道会吐一段字就退出，没有历史
- `--new`：每次敲错都开一段新会话。否则内容会追加进这个目录上一次那段长会话，上下文与会话名都被打乱
- `"$@"` 保留分词，原本带空格的参数不会被拼坏

钩子块在 rc 文件里用一对固定标记圈起来，安装与卸载都靠它识别。那两行标记不翻译——翻了字面串就再也找不到旧块，用户会攒出一堆重复钩子。

读 rc 文件失败时（权限、不是普通文件）命令直接报错，而不是当成「文件是空的」写回去：那样会把用户的 rc 抹掉。

## 与交互界面的关系

两条路共用同一份连接逻辑、同一份配置与同一个宿主。区别只在出口：

| | 管道 | 界面 |
|---|---|---|
| 会话 | 默认不建；`--save` 才建 | 一直在会话里 |
| 输出 | stdout 只有答案 | 整帧重绘 |
| 日志 | stderr | `<数据根>/logs/cli/cli.log` |
| 题 | 不挂，一直等 | 浮层作答 |
| 退出 | 进程结束 | 退出程序，宿主继续跑 |
