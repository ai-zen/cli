# 宿主

一个进程只有一条连接，一条连接只对一台宿主。连哪台由连接屏上那次选择定，或者由这次的 `--server`（含 `AI_ZEN_SERVER_URL`）定。拉起宿主这件事只有客户端做，而且只在连接是本机、又没人应答时做。

## 连本机与连远端

| | 本机 | 远端 |
|---|---|---|
| 什么时候 | 连接屏上选「本机」，或上次选的就是它 | 给了 `--server` / `AI_ZEN_SERVER_URL`，或连接屏上选了「远程」 |
| 怎么找 | 读 `<数据根>/run/host.json` 与 `run/token` | 用给出来的那个地址 |
| 没人应答时 | 用 `npx` 现拉一台（见下） | 只连，绝不拉起 |
| 凭证 | `<数据根>/run/token`，宿主启动时写 | `AI_ZEN_SERVER_TOKEN`；地址是回环时也可以读 `run/token` |

这台是不是本机，判据只有一条：走的是本机发现文件那条路，或者地址的 host 是回环（`localhost`、`127.0.0.1`、`::1`）。它决定两件事 —— 能不能把运行 `ai` 时的目录当成要进入的项目（见[快速开始](./getting-started.md)），以及「上次进入的项目」记在哪一格。

只有人在连接屏上选过的那一份才写进 `<数据根>/cli/connection.json`（`0600` + 原子写）。命令行与环境变量是这一次的表态，不落盘：`ai --server wss://…` 用过一次，不该把默认改成那台。屏上的提交是先验证再落盘，连不上就不写。

## 本机拉起与它的进度

```bash
npx -y @ai-zen/agents-host@<range> serve --ai-zen-dir <数据根>
```

`<range>` 是这次构建所依据的 semver 范围，构建时写进 `dist/`。拉起屏把这件事报成三个会画出来的阶段 —— 解析版本、下载并安装、启动宿主 —— 一次一行，不报百分比。连上那一格不画：屏直接换成会话屏。

| 情形 | 屏上 |
|---|---|
| 拉起来了 | 阶段一行行往下换，连上就换屏 |
| 拉不起来 | 多一行子进程自己说的原因，等 `R` 再拉一次 |
| `Esc` / `Ctrl+C` | 杀掉那个子进程，回连接屏改连别处；不退出程序 |
| 宿主本来就在跑 | 一个阶段都不来，拉起屏一个字节都不画 |

子进程的输出落在 `<数据根>/logs/cli/launch.log`，每次拉起重写，失败时最后一行就是屏上那句原因。

## `/upgrade`

升级分三段，客户端只做第一段：

| 段 | 谁做 | 做什么 |
|---|---|---|
| ① 挑版本 | 客户端 | 问 registry 上各 dist-tag，取 semver 最高的一版 |
| ② 验、记、请退出 | 宿主 | 验这一版拿得到，写下下次该拉哪一版，以升级为理由退出 |
| ③ 装包与拉起 | 启动方式 | 读那一份记录，把这一版装下来再起 |

`/upgrade` 因此是五步：

1. 查：`npm view @ai-zen/agents-host dist-tags --json --prefer-online`。
2. 挑：全部 tag 里 semver 最高的（只认 `latest` 会漏掉「alpha 比正式版新」这种实际发布状态）。
3. 判：跟正在跑的那一版比（`host.version`）。不比它新就停，什么都不告诉宿主 —— 本地跑的开发版不该被「升级」降级。
4. 确认：两档，一次说清目标版本、宿主做的是哪一半、以及这一台机器上连着的其它客户端也会断开。
5. 交：`host.upgrade` 收一个具体版本号。宿主验「这一版拿得到」（磁盘上已经是这一版，或 registry 上确实有这个号），不成立就回 `not_available`，宿主不退出，客户端把它的原话上屏、这一屏照旧连着；成立就先写下那份记录，再以升级专用的理由退出。

回执到了之后客户端回连接屏，屏上说清宿主正在按新版本重拉。装包与拉起都不在客户端做，也不在宿主做：宿主不 re-exec 自己，也不碰 npm。

## `/shutdown`

确认一次之后调 `host.shutdown`，然后回连接屏，屏上说清宿主已关闭。

一台机器一个宿主，所以这一下会踢掉同一台机器上连着的其它客户端，包括别的终端与桌面端。回到连接屏时它不试连也不拉起 —— 试就等于又把刚关掉的那台起回来。之后重新拉起一台，或者改连别处，由人决定。

退出客户端不关宿主：`/exit`、`/quit`、空草稿时按 `Ctrl+C`、连按两次 `Ctrl+D` 都只收掉这一个进程，正在跑的那一段在宿主那边照旧。

## 凭证从哪来

| 来源 | 用在哪 |
|---|---|
| `<数据根>/run/token` | 本机那条路；宿主启动时写这个文件 |
| `AI_ZEN_SERVER_TOKEN` | 显式地址那条路 |
| 连接屏上填的令牌 | 写进 `<数据根>/cli/connection.json`；留空表示用本机宿主的令牌 |
| 显式地址是回环地址 | 设置里没有令牌时读 `run/token` |

没有 `--token` 这个参数：argv 会进 `ps` 输出与 shell 历史。连不上时那句原因先过一遍抹除，令牌原文不上屏。

宿主侧的口径：本机实例只监听回环，对外实例监听所有网卡，那台机器外的客户端凭凭证连进来。所以跨机器访问要么直连那台对外监听的宿主，要么走隧道或反向代理，`--server` 也接受反向代理的子路径。

诊断一条连接而不拉起任何东西，用 `ai --server-status`：把这个地址上宿主的状态按 JSON 打出来（答上了带版本与端点，没答上带原因），退出码 0 / 1。它读的是此刻的事实，不是「有没有发现文件」。
