# 命令

命令在输入行里以 `/` 开头打进去。名字、别名与说明出自同一张表（`src/commands/registry.ts`），所以输入行下面的菜单、`/help` 与这一页不会各说一套。

参数写在命令名之后，按空白切开：`/handoff self` 就是命令名加一个参数。命令名与别名都不区分大小写。

## 忙时不能用的命令

这一段正在跑（宿主报 `working`）时，下面五条按下去会被直接拦下，并说清是「等这一段闲下来」：

| 命令        | 为什么                                                              |
| ----------- | ------------------------------------------------------------------- |
| `/model`    | 写会话行，下一轮请求立刻换模型 —— 一批内部换家，工具调用与思考参数都可能对不上 |
| `/think`    | 同上（思考档位是模型的参数）                                        |
| `/back`     | 撤回要删消息，宿主在跑的时候会拒（「等它停下来再撤回」）             |
| `/handoff`  | 交接要读这一段的完整记忆，宿主在跑的时候会拒（「等它答完再交接」）   |
| `/migrate`  | 同上，而且它还要换记忆                                              |

`/` 菜单在这几条的说明前面会标一句「处理中不可用」，判据与那道门是同一个（`CommandMeta.needsIdle`）。

**会话的新建与切换不受影响**：`/new` `/load` `/sessions` `/ws` 换的只是「看哪一段 / 下一个新会话开在哪」，运行中的那一段留在注册表里继续跑。`/clear`（只清屏）、`/free`（清排队区）、`/pin` `/rename` `/agent` 与配置类命令同样照旧可用。

## 会话

| 命令        | 别名      | 参数                               | 做什么                                                                                                        |
| ----------- | --------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `/new`      |           |                                    | 在当前项目里、用同一个 AgentDefinition 另开一段会话；正在跑的那一段照旧跑                                     |
| `/load`     |           | `-a`、`--all`                      | 换一段已有的会话（`session.list`）；`--all` 跨项目                                                            |
| `/sessions` | `/ps`     | `-a`、`--all`                      | 列会话并切换；本进程挂着的那几段还会说忙闲、在忙什么、排队几条                                                |
| `/ws`       |           | `new [路径]`、`delete <名字或 ID>` | 列项目并切换（`/ws new` 在本机登记当前目录、在远端要一个绝对路径；`/ws delete` 删掉一个项目连同它名下的会话） |
| `/pin`      |           | `on`、`off`                        | 置顶 / 取消置顶这一段（`session.pin`）；不带参数时反着来                                                      |
| `/back`     | `/revert` |                                    | 撤回到你的某条消息之前（`session.rewind`）；撤掉的文字与 Asset 回到输入框                                     |
| `/rename`   | `/save`   | `<名字>`                           | 给这一段改名（`session.rename`），id 不动                                                                     |
| `/title`    |           |                                    | 让模型给这一段重新起个名字（`session.autoTitle`）：自动起名只在第一次答完之后动手，此后要再要一个就点这条 |
| `/form`     |           |                                    | **调试用**：把每一种表单项（文本 / 邮箱 / 单选 / 数字 / 整数 / 布尔 / 多选）摆上屏看一眼；改面板时不用去接一台服务器 |
| `/editor`   |           |                                    | 用 `$EDITOR`、`$VISUAL` 或平台缺省编辑器写这一条消息                                                          |
| `/clear`    |           |                                    | 只清屏，上下文一个字不动                                                                                      |
| `/free`     |           |                                    | 清空排队区（`runtime.agent.clearInbox`），并说清掉了几条；一条都没排着就什么都不说                            |
| `/delete`   |           |                                    | 删掉这一段会话（`session.delete`）；确认那一句先说清消息条数与 Asset 份数                                     |
| `/kill`     |           | `[ID 或名字]`                      | 终止一段会话的 Agent（`runtime.agent.kill`）；会话行与历史保留，下次发送消息时自动重新启动                          |
| `/exit`     | `/quit`   |                                    | 退出客户端；宿主继续跑                                                                                        |

`/rename` 的别名是 `/save`：旧版 `/save <名字>` 干的是改名，那一半留着；保存这件事本身没有了 —— 会话一建就在库里。启动参数里的 `--save` 是另一件事（纯 stdio 那一次调用留成一段会话）。

`/rename` 与 `/title` 的分工：前者写你自己想的那几个字，后者把名字交给模型 —— 名字由谁写的，会话行上记着（`user` / `auto`），能自动改名的那一套只碰模型起的或建行时的占位名。

`/kill` 认人时先认完整 id，再认 id 前缀，最后认名字；对得上好几段就把那几个 id 列出来，不去猜。`/delete` 删完换到本项目里最近的另一段；本项目里没有别的会话时留在原地说清可以用 `/new` 开一段。

## 配置

| 命令      | 别名      | 参数                                                    | 做什么                                                                                               |
| --------- | --------- | ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `/config` |           |                                                         | 打开配置中心（见[配置](./configuration.md)）                                                         |
| `/model`  |           | `[<id>]`、`-a`/`--agent [<id>]`、`-g`/`--global [<id>]` | 换模型：这一段会话、AgentDefinition、或全局兜底                                                      |
| `/think`  | `/effort` | `[档位]`、`-a`/`--agent [档位]`                         | 换思考强度：这一段会话或 AgentDefinition                                                             |
| `/agent`  |           | `[id]`                                                  | 选默认 AgentDefinition；只对以后新开的会话生效                                                       |
| `/mcp`    |           | `[user\|workspace]`                                     | 进配置中心的 MCP 屏，落在那一层；不给参数时进已经有服务器的那一层                                    |
| `/key`    |           |                                                         | 设当前端点的 API Key（进配置中心里那一格）                                                           |
| `/lang`   |           | `[zh\|en]`                                              | 换语言：宿主渲染的句子读 `config.language`，界面读本机偏好；不带参数在两门之间切                     |
| `/reload` |           |                                                         | 让宿主重新发现工具、skill、MCP 服务器与 subagent（`runtime.scope.reload`），再把这一段的事实重取一次 |

`/model` 不带级别参数写会话行，`-a` 写 AgentDefinition，`-g` 写 `config.json` 里的兜底。手上有活的会话换模型或换思考档位会被宿主拒，所以客户端先问一句要不要现在试。

`/think` 的档位来自模型引用的那张档位表；AgentDefinition 级那一档另有一条「不再写这一层」，把定义上属于思考策略的参数剔掉。两档都改不了时如实说一句，不留一个空菜单。

`/reload` 的回执说的是刷了几份、有没有没刷成的：`0/2` 与 `2/2` 是两件事，那一句不合并。

## 交接

| 命令       | 参数              | 做什么                                                                            |
| ---------- | ----------------- | --------------------------------------------------------------------------------- |
| `/handoff` | `[self\|summary]` | 只写一份交接文档（`handoff.start`，`kind: "document"`）；记忆、Agent 与存档都不动 |
| `/migrate` | `[self\|summary]` | 写完文档当场换手（`kind: "swap"`）：记忆换成新的一份，旧记忆成为一段已存档会话    |

`self` 由这一段会话自己的 Agent 写文档，`summary` 另起一个只干这一件事的一次性 Agent 去写。两条命令**不给参数时先问一次用哪种方式**（自交接 / 独立交接 / 不交接）—— 这一问由宿主出，与上下文撞线时那一问是同一份题；显式写了 `self` / `summary` 就不再问。那一屏上按 `Esc` 等于选「不交接」（哪个选项是退路由宿主说，不靠它排在第几位）。两条都不换屏：换手是原地换记忆，会话 id 不变。

换手完成后，接手的那一任会立刻收到一条指令：**读交接文档，然后接着干**（来源标签 `handoff-resume`，优先级高）。断点消息里只有路径、不带全文，所以「谁去读」得有人开口 —— 这条指令就是那一句。只写文档那一档不投它：记忆没换，没人要读。

文档写到哪由宿主说。显式给了执行者时回执是「开始了」；没给时那一问本身就是回执，用户选完才真正开跑。写完那一条带路径的通知会进通知栏。

这一段还没跑起来时（宿主重启之后每一段都是这一种）也不用先发一句话：这两条命令会先启动它（「先唤醒再动手」与发送消息同一条口径），再交接。启动失败则不交接，错误的原文照旧上屏。

两条都要跑一次模型调用，所以执行期间输入框被拦住。

## 宿主

| 命令        | 做什么                                                                                                      |
| ----------- | ----------------------------------------------------------------------------------------------------------- |
| `/upgrade`  | 把宿主换到 registry 上版本最高的那一版（`host.upgrade`）；客户端回连接屏，等宿主按新版本重拉                |
| `/shutdown` | 关掉宿主（`host.shutdown`）；一台机器一个宿主，所以这一下会踢掉同一台机器上的其它客户端，之后客户端回连接屏 |
| `/help`     | 列出命令与各自那一句说明                                                                                    |

`/upgrade` 与 `/shutdown` 都要先确认一次（是 / 否），确认之前一个 procedure 都不调。两条的走法见[宿主](./host.md)。

## 宿主的提问（一张表单）

上下文到了交接线、一个不可撤销的动作之前，或者一个 MCP 服务器在工具调用中途要一句输入时，宿主会发一张表单过来。表单就是 MCP elicitation 的 `requestedSchema`：扁平对象，属性只能是字符串 / 数字 / 布尔 / 单选枚举，数组只允许「多选枚举」。

客户端按表逐格画，**焦点在哪一格、那一格就是活的**：文本/数字直接敲（不必先按回车），布尔回车或空格切换，单选/多选按回车**展开**候选（展开后 ↑ ↓ / ← → 换、多选空格勾，回车收起）；↑ ↓ 在「各字段 + 底部的三个动作」之间换焦点（必填的字段标签后面有一个红色的 `*`）。动作三格说的是**谁做的决定**：`[同意]` 带内容交卷（校验不过不关面板，焦点跳回那一格）、`[拒绝]` 明确说不、`[取消]` 没做决定（Esc / Ctrl+C 同义）。只有一项的表没有另一条路 —— 形状一样，也要走到动作上才交卷。交回去的就是这三态之一（`accept` / `decline` / `cancel`），走 `question.answer`。

不作答就让它挂着：题还在，宿主随后拒绝把话发出去。替用户填一份等于替他决定要不要交接、要不要花这笔钱，所以客户端不填。

## `/` 菜单与 `/help`

输入行里打一个 `/`，下方列出全部命令；继续打字按前缀收敛候选。菜单紧贴输入行向上生长，方向键选，`Enter` 执行高亮那一条，`Tab` 补全命令名。

`/help` 把同一份清单打进转录，一条一行，说明就是菜单上那一句。它不联网，宿主连不上时照样能用。

命令名的候选只按主名与别名匹配前缀；敲一个不认识的 `/xxx` 会说一句「未知命令」。

## 出错时说什么

处理器自己说得清的就用自己的话（写入失败、用户取消、认不出参数）。剩下没接住的，在唯一那个出口收成一句「哪条命令 + 宿主原话」，不重试、不降级、不改状态：命令失败时状态本来就没动，界面下一次重画就是真值。
