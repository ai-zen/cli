# 故障排查

## 连不上宿主

客户端按固定顺序找宿主，先看它走到了哪一步：

1. `--server <url>` 给的地址
2. 环境变量 `AI_ZEN_SERVER_URL`
3. `<数据根>/run/host.json` 里的地址 + `<数据根>/run/token` 里的凭证
4. 以上都没有或连不上：拉起一个宿主（本机实例），等它开始监听

三步诊断：

```bash
ai --server-status          # 打印宿主状态；不拉起、不进界面
cat <数据根>/run/host.json  # 此刻谁在服务：地址、端口、pid
ls -l <数据根>/run/token    # 本机凭证是否存在
```

`--server-status` 在跑返回 0、没在跑返回 1，可以直接写进脚本。`host.json` 里的进程如果已经不在了（被 `kill -9`、机器重启过），文件可能残留：删掉它，或者直接启动宿主，它会覆盖。

远端连不上时先确认三件事：地址的协议前缀（不写时按 `ws://`）、宿主是否以 `--public` 启动（只监听回环时外部连不上）、凭证是否已在那台机器上用 `token create` 造过。

## 界面上的提示

通知栏不进会话转录，`Ctrl+X` 清本会话、`Ctrl+G` 清全部。常见几条：

| 提示 | 含义 |
|---|---|
| 会话启动失败：`{error}` | 唤醒失败：定义读不出来、模型解析不出来、历史形状不对 |
| 恢复失败：`{error}` | 从上次打开的那一段续接失败 |
| 子 Agent `{name}` 失败：`{error}` | 委派返回失败；父那一侧已经收到一条解释 |
| 正在交接，该消息未发送 | 交接进行中不接收输入；`Esc` 放弃交接并恢复到交接前状态 |
| 交接已中断，记忆已恢复到交接前状态 | 你按了 `Esc` |
| 尚未进入工作区：`@` 补全暂不可用 | 还没选工作区，文件清单无从获取 |
| 待答问题读取失败 / 通知读取失败 | 连接断了；先看宿主是否还在跑 |

## 命令被拒

「处理中不可用」：`/model`、`/think`、`/back`、`/handoff`、`/migrate` 改的是这一段正在使用的设置，agent 跑着的时候不执行。等这一批跑完，或用 `Ctrl+C` 中断。

执行 `/title`、`/handoff`、`/migrate` 期间输入框被拦住：这几条要调用模型，几十秒。这时打的字不会生效——不是丢了，是被拦住。

## 新加的能力不生效

按顺序查三处：

1. 文件放对目录了吗。工具的约定目录是 `tools/`，技能是 `skills/<id>/SKILL.md`，子代理是 `sub-agents/`；放在 `agents/` 里的是 agent 定义，不是能力
2. 名字被更近的一层占住了吗。同名以近的为准：项目里的同名文件会盖住数据根里的那一份
3. 宿主侧的刷新时机。`autoRefreshTools` 为 `off` 时只能靠 `/reload`；为 `outer-loop-start` 时要等下一次被叫起来

`/reload` 的结果会写清刷新了几个能力容器；「当前没有已创建的能力容器」表示这一段还没被使用过，下次使用时会按新配置创建。

## 按键没反应

不同终端的按键编码差异很大（尤其 macOS 的 Option 与 `PgUp`/`PgDn`）。打开按键诊断：

```bash
AIZ_DEBUG_KEYS=1 ai                       # 追加写到 <数据根>/logs/cli/keys.log
AIZ_DEBUG_KEYS=1 AIZ_KEYS_FILE=/tmp/k aiz # 写到指定文件
```

这个开关在进程启动时读一次，运行中再设无效。判读方法：

| 现象 | 结论 |
|---|---|
| 按了键，日志里没有新增行 | 键没到应用：被系统快捷键或终端键位映射截走 |
| 有行，但 `input` / `flags` 与预期不符 | 序列收到了，是匹配规则的问题 |
| 有行且 `raw=false` | 终端不在 raw 模式，键被终端自己解释了 |

`Alt` 组合不作为快捷键，这是刻意的：它在不同终端、shell、tmux 与输入法下表现不一致。用 `Ctrl` 侧的等价键。

## 日志

| 位置 | 内容 |
|---|---|
| `<数据根>/logs/cli/cli.log` | 客户端自己的日志，单份 2MB，保留两份（`cli.log.1`） |
| `<数据根>/logs/` | 宿主的日志 |
| `<数据根>/run/host.json` | 宿主的地址与进程号，用于判断「它在不在」 |

管道模式不建文件：日志全部写 stderr，stdout 只留给结果。

## 升级

```bash
# 界面里
/upgrade
```

它查发布标签里的最高版本、比版本、确认，然后让宿主记录下次启动的版本并以升级为由退出；装包与拉起交给启动方式。这期间本机其他客户端（含桌面端）会断开。

两条常见失败：

- 「已是最新版本」：标签里没有比当前更高的可解析版本
- 「无法获取发布版本」：registry 不可达，或标签里没有可解析的版本号。检查网络与 registry 配置

宿主升级失败时会说明原因并保持原版本运行；会话与历史在数据库里，不受影响，但中断的那一次请求不会自己重发。

## 三个「结束」的区别

| 动作 | 会话 | agent | 宿主 |
|---|---|---|---|
| `/kill` | 保留 | 终止 | 继续跑 |
| `/delete` | 删除（消息与素材一并删除） | 终止 | 继续跑 |
| `/shutdown` | 保留 | 全部终止 | 关闭，界面回连接屏 |
